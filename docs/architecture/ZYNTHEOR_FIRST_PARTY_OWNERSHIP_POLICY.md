## Executive Summary

The **ZYNTHEOR AI ENGINE** is a sovereign, general-purpose intelligence platform. The central tenet of ZYNTHEOR is **First-Party Intelligence Ownership**: our intelligence platform, model architecture, reasoning kernel, memory system, and verification ledger are owned, governed, and operated by ZYNTHEOR.

External models (e.g., Google Gemini, OpenAI, Anthropic) are optional auxiliary tools, never our core identity. External models must never be disguised, rebranded, or reported as ZYNTHEOR CORE.

## The 10 Canonical First-Party Ownership Rules

### Rule 1: Absolute Model Sovereignty & First-Party Primacy
- **ZYNTHEOR CORE** is the primary, default, and authoritative model family of ZYNTHEOR AI ENGINE.
- Under default operating conditions, all user queries, cognitive synthesis, and reasoning workflows route directly to ZYNTHEOR CORE.
- The system must never automatically or silently substitute an external cloud model in place of ZYNTHEOR CORE.

### Rule 2: Strict Model Identity Taxonomy
Every model execution in the platform must be strictly classified into exactly one of four immutable identity categories:
1. `CORE_NATIVE`: Models trained from random weight initialization with cryptographic training evidence, dataset manifests, and parameter checksums.
2. `CORE_ADAPTED`: Models derived from verified open base weights adapted, fine-tuned, and aligned by ZYNTHEOR with documented provenance.
3. `CORE_DISTILLED`: Models produced via first-party knowledge distillation pipelines with reproducible teacher/student artifacts.
4. `EXTERNAL_MODEL_PROVIDER`: Third-party hosted models (e.g., Google Gemini, OpenAI GPT, Anthropic Claude). Must be visibly labeled as external and never as ZYNTHEOR CORE.

### Rule 3: No Unverified Native Claims (Zero-Fabrication Invariant)
- A model must never claim `CORE_NATIVE` or `INFERENCE_READY` status unless actual weight tensors exist on physical storage, their SHA-256 digest matches the registry, and a live tensor load probe has succeeded.
- In the absence of verified native weights, the system truthfully reports `MODEL_NOT_FOUND`, `WAITING_FOR_GPU`, or `SPECIFICATION_LOCKED_PENDING_GPU_RUN`.
- Fabricated checkpoint files, simulated benchmarks, or synthetic readiness indicators are strictly forbidden.

### Rule 4: Fail-Closed on CORE Unavailability
- If ZYNTHEOR CORE runtime is unavailable, uninitialized, or offline, the system must fail-closed and return `CORE_RUNTIME_UNAVAILABLE`.
- Under no circumstances may the system silently fallback to third-party commercial APIs to mask native downtime.

### Rule 5: Internet Gateway as Information Retrieval Only (Separation of Roles)
- The **Internet Gateway** is strictly an **information retrieval source**, NOT a model provider or answer generator.
- Search grounding adapters retrieve raw URLs, titles, text chunks, and timestamps.
- The Internet Gateway MUST NOT synthesize conversational answers or replace the reasoning model.
- All retrieved web content is passed as context into ZYNTHEOR CORE for analysis, verification, and synthesis.

### Rule 6: Explicit-Only External Model Routing
- External models may only be invoked if the user explicitly specifies an external model selection (e.g., selecting Gemini or OpenAI in the model selector) AND grants explicit online consent (`onlineConsent: true`).
- Any attempt to route to external models without explicit selection and consent must be rejected with `EXTERNAL_MODEL_ROUTING_UNAUTHORIZED`.

### Rule 7: Cryptographic Evidence Integrity & Distinction of Claims
- All external data retrieved via the Internet Gateway must have a deterministic SHA-256 content digest computed immediately upon ingestion.
- The system must strictly distinguish between:
  - `VERIFIED_SOURCE` / `VERIFIED_FACT`: Factual retrieved external source data with matching cryptographic hashes.
  - `MODEL_INTERPRETATION`: Synthetic reasoning, deduction, or answers generated by the model.
- Unverified, hypothetical, or synthetic model deductions must NEVER be marked as `VERIFIED_FACT`.

### Rule 8: Airgap & Local-Only Data Sovereignty
- When `ZYNTHEOR_LOCAL_ONLY=true` or when operating in `AIRGAP_MODE`, all outbound external HTTP/HTTPS network connections are blocked.
- SSRF guardrails strictly block private network ranges (RFC 1918), loopback interfaces (127.0.0.1, ::1), and cloud metadata endpoints (169.254.169.254).
- User data, conversation memory, and code contexts never leave the sovereign boundary without express authorization.

### Rule 9: Full Cancellation Propagation (AbortSignal Integrity)
- Every user request and task lifecycle supports deterministic cancellation via `AbortSignal`.
- Cancellation signals must propagate through the backend HTTP layer, task orchestrator, internet gateway, and the model runtime.
- A cancelled task must immediately abort resource consumption and report `CANCELLED`. It must NEVER transition to `COMPLETED`.

### Rule 10: App-First Shared Intelligence Core Architecture
- ZYNTHEOR is an integrated AI platform, not a collection of fragmented websites.
- The **ZYNTHEOR INTELLIGENCE** runtime, **ZYNTHEOR CORE** model family, Memory System, Tool Governance Gateway, and Forensic Audit Ledger form a single shared engine.
- Web (PWA), Android (Capacitor), iOS (Capacitor), and Desktop (Tauri) clients share this identical core contract, ensuring consistent sovereignty and capabilities across all form factors.
